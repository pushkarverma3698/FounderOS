# M0.5 — Founder Time Baseline (LIVE MEASUREMENT)

> **Clock started: 2026-08-06. Two-week window closes: 2026-08-19.**
>
> This is the benchmark **every later milestone must reduce**. Without it, FounderOS can become
> technically better without making the founder's life meaningfully easier — and M6 has nothing
> to prove itself against.

## Why this exists

The first KPI is **not** "how autonomous is FounderOS?" It is **"how much founder work
disappeared?"** Saving 20 hrs/week at 40% autonomy beats 90% autonomy that saves none.

M6 (Evolution Engine v1) is only considered proven when a capability it proposed, built and shipped
moves a business KPI **or a number in this file**. That requires a *before*. This is the before.

## How to log (keep it cheap — friction kills baselines)

Round to the nearest 15 minutes. Log at end of day, or whenever you remember. **An incomplete log
beats an abandoned one** — a missed day is recorded as a gap, not backfilled from memory.

Categories (from the approved plan):

| Category | Counts as |
|---|---|
| **Prompting** | Writing/rewriting prompts, re-asking, steering an agent mid-task |
| **Reviewing** | Reading diffs, PR review, checking agent output, verifying claims |
| **Planning** | Deciding what to build, prioritising, roadmapping, this kind of session |
| **Researching** | Reading docs, searching, comparing tools/models/approaches |
| **Coding** | Writing code by hand |
| **Debugging** | Diagnosing failures, reading logs, reproducing bugs |
| **Deploying** | Merges, deploy babysitting, prod verification, incident response |

## Standing rule

A milestone that reduces none of these is, by the Constitution, not obviously worth building.

## Open decision

than wait on a build. A `/time` Telegram command would cut the friction, but it is an 8th command
against the "7 essential commands" rule, so it needs an explicit founder call. Until then: this file.
