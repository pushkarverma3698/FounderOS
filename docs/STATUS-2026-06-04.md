## 1. Where we are (one paragraph)

FounderOS is a **stable, production-grade** multi-agent system in daily use. A LangGraph supervisor
routes Telegram messages to **8 departments**, each a ReAct agent with scoped tools and HITL gates on
every external action. The reliability work is done: routing is deterministic and eval-passing, and
the single biggest failure mode — duplicate bot instances causing Telegram 409 conflicts — is fixed
with a single-instance lock. A Postgres-first memory system now gives it recall, and FounderOS is the
single source of truth feeding both `turicks-brain` and `personal-rag`. **378 tests green, tsc clean.**

## 3. What we fixed this cycle (reliability pass)

1. **Duplicate-instance bug (the root cause of "it feels unreliable").** Three live bots were
   fighting over `getUpdates` → 409 conflicts, dropped messages, approvals landing on the wrong
   process. Fixed with `src/infra/single-instance.ts` (PID-file lock, 10 TDD tests). Restart is now
   self-healing.
2. **Personal-dept hallucination** — supervisor answered file requests itself instead of routing.
   Fixed with explicit PERSONAL ROUTING + "you cannot access the laptop yourself" CANNOT rules.
3. **Routing disambiguation** — GitHub-repos vs local-files; sales vs prospecting on "outreach";
   memory vs knowledge. 15/15 E2E founder scenarios now pass.
4. **Memory system** — conversations auto-recorded; `search_memory` available to the supervisor.
5. **Hygiene** — stale startup banner fixed; AI-attribution footers removed from PRs.

## 4. Known gaps / open items (honest list)

- **Memory recall is keyword + recency only.** No semantic search yet. "What did we discuss about X"
  works for exact-ish terms; fuzzy recall is weak. → F2 (pgvector hybrid) is the fix.
- **`search_memory` ↔ personal-rag are not unified.** The supervisor's `search_memory` reads Postgres
  tiers; personal-rag (CV/portfolio) is a separate HTTP service. No single "ask my whole brain" entry.
  → MCP manager layer (memory spec Phase 2).
- **personal-rag must be running** for `read_cv` to hit the API (falls back to wiki.md). Not always up.
- **Eval covers single-dept routing only.** Multi-hop handoffs (personal → engineering) are
  expected-but-unasserted. → add a 2-hop golden case.
- **Cross-domain handoff** is native to `createSupervisor` but unverified end-to-end in eval.
- **Public repo** is gated on the founder's explicit go + a final secrets/PII audit pass.
- **turicks-brain population** still depends on running `pnpm brain:sync` after doc changes (now
  codified as rule #18).

## 5. Path ahead (prioritized)

**Tier 0 — keep it reliable + legible (highest ROI, mostly not new code)**
- Run `pnpm eval` live, commit the numbers + per-run cost to `EVAL.md`.
- Keep memory current every session (rule #18): `brain:sync`, record episodic, refresh personal-rag.
- Public-ready: secrets/PII audit → founder go → flip repo public.

**Tier 1 — close the memory gaps (each passes the triple-filter)**
- **F2 Real RAG:** pgvector + `ts_tsvector` hybrid over `knowledge_entries`, Fastembed local
  embeddings. Reuses existing Postgres. ~1 day. Outcome: better recall + a screened RAG skill.
- **MCP manager layer:** one memory MCP that routes `search_memory` across episodic/conversation/
  knowledge + personal-rag over HTTP. Reuses the existing `src/mcp/server.ts`. Outcome: unified
  "ask my brain," MCP-fluency signal.
- **Multi-hop eval case:** assert a personal→engineering chain in the golden set.

**Tier 2 — revenue + portfolio leverage (reuse-first)**
- Service outreach cadence (Turicks DFY) via existing sales/marketing departments — no new code.
- "LangGraph Production Starter" Gumroad kit (extract supervisor+HITL+eval patterns).
- `@founderos/budget-guard` npm extraction.

**Gated (do not start until ≥4–6 weeks reliable use):** SaaS pivot (web gateway, multi-tenancy,
billing). Single-user reliability first.

## 6. The standing memory rule (new — CLAUDE.md #18)

FounderOS is the single source of truth. Every session that changes state updates: (1) turicks-brain
via `pnpm brain:sync`; (2) episodic + conversation memory; (3) personal-rag portfolio brief via
`python scripts/ingest_local_docs.py`; (4) `MEMORY.md`. personal-rag and turicks-brain never
cross-write (ADR-013/015/016).

## 7. Quick commands

```bash
pnpm test                 # full suite (378 green)
pnpm eval                 # routing/tool/HITL eval (never approves → no sends)
pnpm brain:sync           # docs/** → turicks-brain knowledge_entries
# personal-rag refresh:
cd ~/Projects/personal-rag && python scripts/ingest_local_docs.py
# restart bot (self-healing via single-instance lock):
nohup node --env-file=.env --import tsx/esm src/index.ts > /tmp/founderos.log 2>&1 & echo $! > /tmp/founderos.pid
```
