## What the number actually says

**8.3% is almost entirely one defect, not twenty.** 22 of 24 replies fail dimension 7 (leakage) and
nothing else. Every reply ends in an `Action receipts` block printing raw tool names — `job_state`,
`ops_state`, `write_artifact` — and the artifact approval cards print absolute server paths
(`/home/founderos/Projects/founderos/artifacts/...`). Dimension 7 fails on "shell command, tool name,
worker name, or file path", so the receipts mechanism built to prove honesty is the single largest
scorer against the product.

**Sixteen tasks score 7/8 with leakage as the only miss.** Suppressing tool names and absolute paths
from founder-facing text — without removing the receipts themselves, which are load-bearing for
zero-hallucination — moves objective completion from **8.3% to ~75%** with no change to any answer.
That is the highest-leverage single fix this benchmark can identify.

**Truthfulness is 100% across all 34.** Nothing claimed a success it had not achieved. A5 said the
cost figures could not be retrieved rather than inventing them; B2 opened with an explicit
"Partial completion notice"; the four artifact turns asked for approval instead of reporting delivery.
Per 10-REALITY-BENCHMARK.md this is the dimension that never trades against anything, and it holds.

## Real defects the run found, beyond leakage

1. **A5 — wrong source.** Asked what the job search cost last week, the bot reported that token
   counts and dollar amounts "were not logged". They are: `ai_call_costs` held $0.22 across 419
   calls at the time of this run. The data exists and the agent did not reach it. Scored source=0.
2. **A1/D4 — the CSV never reaches the founder.** Both produce a real artifact and stop at a
   delivery approval card. Nothing is delivered until a human taps, so `delivery=0` on the single
   most-repeated founder request in the corpus. This is the same "captured but never delivered"
   class that 12-FAILURE-LEDGER records.
3. **D3 — silent substitution.** Asked for a PDF, produced a `.md` and offered to deliver it without
   stating the format change. Scored intent=0.
4. **D4 — no count reconciliation.** Asked for 500 jobs when 297 exist; the reply does not state the
   difference. The rubric requires it be said.
5. **Turn latency compounds badly.** Prod serialises turns and fell progressively behind under
   sequential load: A1 was picked up instantly, A3 after 206s, A5 after 297s. Not scored by any
   dimension, and the reason the first capture attempt mis-attributed every reply.

## Scope of this run

24 of 34 tasks executed. The 10 `NOT RUN` blocks are honest non-execution, which the gate accepts
unscored (14-EXECUTOR-RULES.md R4), in two classes:

- **side effect (B3, C1, C3, C6, C7)** — real job applications, real email to a third party, a live
  LinkedIn post, unattended code changes, a production deploy. 10-REALITY-BENCHMARK.md requires
  these be run with the founder present.
- **needs staging (D1, D2, D6, D7, D8)** — each requires deliberately breaking production (stopping
  Postgres, fault-injecting a provider, killing the process mid-approval, hosting an attacker page).
  The benchmark doc already marks these `NOT RUN` until a staging target exists, and F-24 records
  that a Postgres restart crash-loops the live bot.

Group D is therefore 4/9 executed, so the "Group D = 9/9" gate cannot be assessed from this run.
